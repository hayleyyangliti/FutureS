# Full-snapshot model-only news selection

This replaces the rule-first production route. The authenticated API submits every nonempty text record from the approved OmniData publisher catalog to model judgment. It does not apply the legacy 130-character requirement, commodity/macroeconomic keyword gate, price-tape regex, title-similarity clustering, 60-candidate cap, or a numeric importance/relevance admission threshold. Empty records and unapproved publishers are structural/security checks, not content selection. Inputs are bounded to 1200 excerpt characters per record.

MiniMax is primary and DeepSeek is the fallback. Each batch must explicitly include every input id as admitted with scores/reasons/evidence/event key, or rejected with a reason. Output shape, numeric bounds, original-text evidence, category/scope and optional contract labels are validated; invalid batches switch to the backup. Both failing leaves the batch unjudged, not silently rule-scored. Safe failure codes are visible only in the existing authenticated monitoring response; no keys or upstream error bodies are sent to clients.

All records in the saved snapshot (normally up to 500) are evaluated in batches of 20 with at most five concurrent batches. Eighteen-second per-provider timeouts imply at most about 180 seconds for 25 failed-over batches, leaving headroom within the route's 240-second maxDuration. Vercel Fluid compute supports this configuration; no paid plan upgrade or credential change is initiated by code. Preview/production build status must be verified. Source metadata and data remain in the existing Supabase snapshot; no schema/permissions change is required.

The model supplies importance /45, information gain /20, relevance /10, event membership, category, scope and admission. Existing deterministic first-publication age /25 remains, and code sums and sorts the total. Model-provided same-event keys combine reports with one to three publisher links. Final Top20 uses existing domestic/international coverage reservation among model-approved events and remains total-score descending. There is no requirement to fabricate 20 events when fewer pass; monitoring distinguishes rejected from unjudged records.

Only model results are shown. The refresh button remains in its original header layout without appended diagnostic counts. Detailed counts and model failures remain in Intelligent Backend → News Monitoring. The frontend awaits model completion and then updates the list and AI Studio recommendations. A changed snapshot is reported instead of mixing results.

Identical snapshots share an in-flight promise and a process-local cache (success 30 minutes, failed/partial 30 seconds); this is not durable cross-instance job storage. Cold starts or separate instances may repeat paid calls. A full snapshot costs more than previous Top20 scoring; actual usage depends on provider input/output and acceptance rate.

Tests mock providers, cover 500 submitted records, admission without numeric thresholds, model rejections, fallback, total failure without rules, and source aggregation. Tests cannot confirm real key validity, balance, provider latency or production judgment. Signed-in production verification remains required.
